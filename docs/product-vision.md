# 陪伴定位与多年维护

状态：长期陪伴、回顾早年重要经历、未来使用常开硬件、协助日常小任务，以及性格养成与开关控制的静默微调已由用户提出。本文中的具体交互与实现策略为建议，尚未实现。

## 一、产品核心

yf 的主要价值是陪伴的连续性：知道用户近期在经历什么，能在相关的时候想起过去，也允许用户主动翻看多年以前的往事。简单任务作为陪伴过程中的实用帮助逐步接入。

希望实现的体验：某一年一起讨论过毕业、搬家或一次旅行，几年后用户问“你还记得那次吗”，yf 可以找到有来源的旧记录，说明发生时间并回顾细节。没有记录或细节不确定时明确说明，不编造共同经历。

## 二、三种使用方式

| 方式 | 体验 | 数据使用 |
| --- | --- | --- |
| 日常陪伴 | 聊近况，延续已有话题，记住用户确认的偏好与重要进展 | 有预算的近期上下文、会话摘要与少量相关记忆 |
| 回忆往事 | 按年份、人物、事件或关键词查找，回看原始片段 | 历史档案的分页查询、分层索引与事件来源 |
| 生活小事 | 查时间、定闹钟、发起电话等 | 设备能力与明确的执行回执，不只输出一句自然语言 |

日常聊天优先保持响应速度；回忆模式可以分步扩大搜索范围，并允许用户打开原始记录。记录丰富也不意味着每次聊天都加载多年历史。

## 三、记忆与关系的连续性

- 重要事件可由用户标记“珍藏”，建议长期保留原始证据、日期与上下文；事件自动识别只作为候选，不能据此擅自删除其他经历。
- 日常信息可以压缩和降低召回权重，珍藏回忆不因多年未提起而自动清除。
- 记忆页提供时间轴、搜索、来源、修正、导出与删除。阶段摘要是导航，不能替代唯一的历史原文。
- 人格从可选初始类型出发，经过长期互动逐渐养成；初始档案、当前档案与成长依据独立于模型保存并有版本记录。更换供应商或本地模型时继续使用这些档案，实际语气需用样例回归评估。
- 探索可以逐渐形成兴趣、问题与学习记录。用户开启“学习成长”后，后台自动筛选、脱敏、整理对话并进行微调，评估通过后自动启用；用户可以查看或暂停，不必逐批手动处理。数据集预览与导出仍作为可选管理能力；详细边界见 [性格与学习设计](personality-and-learning.md)。
- 自动提取、主动问候、周年回忆等交互需要单独确定。主动功能可设置时段、频率和关闭方式，不能把安装应用等同于同意持续打扰。

## 四、按多年使用设计

| 关注点 | 建议策略 |
| --- | --- |
| 数据所有权 | 用户可导出对话、事件、来源、时间与附件目录，不以某个向量库作为唯一保存格式 |
| 可迁移 | SQLite 与可选附件使用清晰的数据目录；逻辑导出采用带版本的 JSON / JSONL，便于跨设备恢复 |
| 可重建 | 向量与检索索引作为派生数据；更换 embedding 模型后能从档案重建 |
| 可恢复 | 数据层早期提供一致性备份与恢复；在线 SQLite 使用备份接口或经过验证的一致性快照，避免只复制正在写入的单个文件 |
| 备份保护 | 根据可接受的数据丢失窗口制定计划，建议每日备份，并定期将加密副本保存到另一物理设备；恢复需要的密钥单独妥善保存 |
| 长期兼容 | 数据版本与迁移脚本入库；升级前备份，用旧数据样本验证迁移与恢复 |
| 存储增长 | 展示档案与附件占用，支持归档和用户控制的清理；容量不足时告知，不悄悄删除珍藏 |
| 可维护 | 记录依赖、发布与关键决定；保持模块边界，避免依赖某个供应商专属的会话状态 |

多年可用依赖持续维护和可验证的恢复机制。Git 仓库只保存代码和设计；用户记忆需要独立备份，不通过把聊天记录提交 Git 来实现。

## 五、未来的常开主机

先在当前 Windows 电脑开发和运行，再考虑迁移到 Mac mini 或其他常开设备。后台服务保持跨 Windows / macOS / Linux 的边界，操作系统专属能力放在各客户端适配器中。

迁移流程应覆盖：创建一致性备份 → 在新主机安装兼容服务 → 恢复数据并重新配置凭据 → 验证记忆与任务 → 切换客户端地址。切换期间只保留一个可写主库；新主机稳定前保留原主机的可恢复副本。历史任务的执行回执也应随数据迁移，避免重放电话等操作。

常开服务可提供稳定的聊天与记忆入口，但不能代替设备自身的闹钟、电话等系统功能。Mac mini 是否运行本地模型、需要多少内存，应在模型选择和实际使用量明确后决定；现阶段无需先采购硬件。支持 macOS 后端也不等于首发包含 macOS 桌面客户端。

## 六、首版陪伴体验建议

先提供少量初始性格模板、称呼与文字聊天，并让性格通过可追溯、可回滚的增量更新逐渐养成。回忆页突出重要事件与时间轴；原始聊天、事实记忆、珍藏事件和成长记录有清晰区别。先预留对话样本来源与数据集导出，再依据模型和硬件实现训练。语音陪伴、照片回忆和主动联系作为后续交互迭代，依用户偏好确定范围。
