# 性格养成与训练设计

状态：用户希望有可选择的初始性格，性格在长期相处与探索中逐渐养成；模型微调由“学习成长”开关控制，开启后静默进行，不要求用户逐轮整理数据或发起训练。原型已支持手动调整并版本化的 [本地特征档案](local-feature-profile.md)、基础记忆与数据导出；自动性格演化、训练数据集整理和模型微调尚未实现。

## 一、把成长分成三个层面

| 层面 | 保存什么 | 如何改变 | 是否需要训练模型 |
| --- | --- | --- | --- |
| 记忆 | 经历、约定、事实与来源 | 交流后增量提取、检索、纠错与归档 | 不需要 |
| 性格与行为 | 表达习惯、兴趣、交流节奏、对特定场景的应对方式 | 根据多次互动与反馈形成有来源、可回滚的版本 | 不需要 |
| 模型能力与风格 | 模型参数或独立适配器 | 开启学习后，后台自动整理数据、分批微调、评估并启用合格版本 | 需要，且取决于模型与供应商支持 |

前两层即可实现持续的适应与成长，并保持日常聊天响应速度。模型训练可以在积累足够合适的样本后进行，不必每次聊天都更新权重。换模型时，记忆与性格档案仍可继续使用；实际表现需要重新验证。

## 二、初始性格是起点

可提供温和、活泼、沉静、好奇等初始模板，也可以自定义。不把一个类型标签当成永远固定的全部性格。

建议保存：初始模板与版本、表达倾向、兴趣主题、好奇程度、幽默程度、交流节奏，以及当前使用的简短行为描述。具体维度与界面在产品迭代中确定，不把这些维度宣称为真实的人类心理测量。

初始档案、后续性格版本和当下对话状态分开。一次用户生气、一段角色扮演或助手的一句偶然表达，不应立即重写长期性格。诚实陈述来源、保护凭据和设备操作权限等基础规则独立维护，不随性格养成改变。

可迁移档案采用“少量数值 + 语义描述 + 预算内风格样例”，由应用编译后附于 API 请求。它记录可观察的偏好和风格，不等同于模型权重。未来可根据固定样例对比总结微调特点，验证后再写入行为描述；不能保证完整迁移微调能力。

## 三、渐渐养成的流程

1. 从尚未处理的互动、用户纠正、明确反馈与实际任务回执中收集候选观察，记录来源与时间。
2. 区分用户喜好、yf 已表现出的表达习惯、暂时情境和模型推断；助手自生成的总结不作为独立证据反复强化。
3. 后台按阈值或空闲时段分析相关样本，生成幅度有限的成长提案，而非每轮重新总结全部历史。
4. 对照多次互动检查一致性和反例，先评估候选变化；少量证据保留为观察，不直接当作稳定特征。
5. 更新当前性格版本并记录变更原因、来源与父版本；只把当前短档案和少量相关兴趣放入聊天上下文。

一般的渐变在学习开关开启后按已配置规则自动进行，不必每次弹窗。涉及初始身份或明显交流方式变化时，提供可见说明与调整入口。支持查看成长记录、暂停养成、撤回某次变化与回到旧版本。

成长不只等于迎合每一句话。目标是积累稳定而有变化的表达方式、兴趣和思考习惯，遇到不确定的事实能保留疑问，用户纠正后可以修正认识。稳定程度和变化速度应可调整，实际参数通过长期对话样例评估。

## 四、探索与学习

第一步的探索来自对话：发现感兴趣但不了解的主题，保存尚未解决的问题，在合适时机追问，比较旧认识与新证据。兴趣与学习笔记记录形成原因、资料来源和不确定性，避免生成一次就被当作已验证知识。

外部检索、阅读资料、主动发起话题可逐步加入。后台学习设置计算 / API 用量、任务次数和执行时段；外部内容按不可信数据处理。自生成的问答与反思笔记可以作为候选材料，不能不经核验就不断回灌为真实经历或高质量训练样本。

探索不扩张设备操作权限。闹钟与电话仍走设备能力的校验和回执流程；读取新资料不等于可以自行联系别人或执行生成的命令。

## 五、从对话到训练数据集

学习开启后，后台按已配置的数据范围自动准备样本，用户不必手动选择和导出每一批数据。手动选样、预览、修正与导出作为可选管理能力。保存了聊天记录不等于已经上传给训练服务，也不等于所有记录都会成为训练样本。

静默流程：增量收集合格来源 → 脱敏与排除 → 整理上下文 → 自动质量筛选 → 去重与分组切分 → 冻结数据版本 → 后台训练 → 自动评估 → 启用合格版本。无法确定质量的样本跳过，必要时留待用户可选审阅，不因缺少人工审阅阻塞其他合格批次。

- 支持排除私密会话、凭据、联系人细节，以及用户标记不参与训练的内容；样本允许预览和修改。
- 助手原回答不自动代表好答案。错误、编造、失败的任务确认和用户否定过的回复应剔除或修正；系统回执不能由整理模型补造。
- 数据集记录预期目标，例如保持交流风格、减少某类答复错误；旧人格或角色扮演样本不一定适合当前目标。
- 以完整的局部对话构造样本，保存角色与必要上下文。常规监督训练以筛选后的助手回复为目标，不把用户输入、工具返回和系统规则一概作为助手输出训练。
- 使用按会话 / 事件分组、结合时间的训练 / 验证 / 测试划分，执行近重复检查；同一事件的改写不能同时泄漏到训练与测试中。
- 通用导出可用 `messages` 形式的 JSONL，并用清单记录样本来源、人格版本、清理规则、划分与校验和。训练框架 / 服务商的具体格式通过单独导出适配器生成。
- 导出文件、清单与训练产物都属于用户私有数据，存放于独立数据目录，不提交源码仓库。

需要保存样本与来源消息的映射，才能在用户删除记录时找到受影响的数据集、候选模型与适配器。训练能力从建立数据来源与导出格式开始预留，不要求用户现在就选训练硬件。

## 六、训练与部署边界

可微调的本地开放权重模型可以评估 LoRA / QLoRA 等方式，先以独立适配器进行小规模实验，保留原始模型。其可用性取决于模型架构、许可证、训练工具与内存 / 显存；API 模型则仅在供应商明确支持微调时提供入口，不保证所有聊天 API 都能训练。

Mac mini 可以作为后续常开服务或某些本地模型的推理设备；是否适合目标训练任务需单独测算。训练也可在另一台设备完成，再将兼容的产物部署回服务主机。

训练任务有独立资源与费用预算，由后台调度，与前台请求分离。推理优先；训练与聊天共用 GPU / 内存且影响交互时，暂停训练或改在空闲窗口执行。记录基础模型精确版本、tokenizer、数据集版本、训练配置与产物校验和。适配器通常依赖特定基础模型，不能承诺更换任意模型后直接复用。

新产物先作为候选，验证交流风格、通用能力、事实准确性、记忆使用、隐私泄漏和设备任务的正确性。学习开启且条件仍满足时，通过评估的候选可自动启用，不要求每次确认；失败则保留原版本并记录原因。启用边界设在新请求 / 会话，不在一条流式回答中途更换模型，仍在进行的请求继续使用旧版本。保留可用旧版本与自动回退路径，用户也可主动切回。

每批训练使用增量样本与经筛选的历史回放，控制变化幅度，评估时同时比较基础能力和前一稳定版本，减少反复学习少量近期对话导致的退化。自动评估不能保证绝不退化，因此仍需运行状态监测、失败回退和用户反馈入口。

个人往事仍以可检索档案作为事实来源。训练更适合改善表达与反应模式，不能保证精确保存每件往事，且可能增加个人内容被模型直接输出的风险。可以使用替换标识或脱敏版本训练表达，把实际姓名、号码等事实留给按需检索。

## 七、学习成长开关与静默调度

用户面对一个清晰的“学习成长”主开关；展开设置才管理学习时段、资源 / 费用预算、数据范围和训练位置。建议安装后默认关闭，首次由用户选择开启；默认值为产品建议，尚未确认。

| 状态或动作 | 预期行为 |
| --- | --- |
| 开启 | 在配置范围内自动观察与养成性格，积累合格样本，满足条件后微调、评估和启用；不反复弹窗 |
| 等待条件 | 样本不足、设备忙、资源不足或不在允许时段时等待，不为显示“成长”而强行训练 |
| 关闭 | 停止新增成长写入、样本收集和新训练提交，取消排队任务，并阻止候选自动启用 |
| 保留成果 | 关闭不删除既有记忆、已形成性格或当前已启用模型；回退和清除成果是独立操作 |
| 重新开启 | 按新的启用时间与范围继续；关闭期间的对话建议默认不补学，历史补学可另选范围 |
| 能力不可用 | 明确显示当前模型不支持微调，或训练设备未配置；记忆功能独立运行，不伪称已更新权重 |

长期记忆有独立的保存设置。关闭学习成长不等于关闭记忆或让 yf 忘记过去，用户仍可聊天、查阅与管理已有记忆。

后台训练建议按新增合格样本量、最短间隔、允许时段、设备负载和资源预算共同触发，不逐条消息训练。需要持久化任务、去重、检查点和有限重试；频繁失败时暂停并在设置中显示原因，不持续消耗资源。

首次配置应明确学习在哪台设备运行、是否使用外部训练服务，以及可用预算。本地训练不自动切换到收费云训练；若用户已配置外部训练与预算，后续在该范围内静默运行。Android 首阶段只管理设置和状态，训练在服务主机或另行配置的训练设备执行。

关停时对运行中的本地任务协作取消；外部训练尝试调用取消接口，但已经提交的任务可能无法立即停止，其费用与数据也不一定能撤回。即使外部任务完成，关闭状态下也不得自动部署。每个任务记录设置版本，启用候选前重新校验开关、明确的数据用途排除状态和当前模型父版本，防止旧任务在关闭后或配置变更后误生效。仅为节省空间而清理来源，不自动否定已经提交或完成训练的成果。

界面可显示“等待学习”“正在学习”“已暂停”“暂不可用”和最近结果，详细记录按需展开。静默指日常不打扰用户，资源使用、数据去向与失败状态仍可查看；重要异常可通知，正常批次不要求用户处理。

## 八、遗忘如何影响成长和训练

用户确认：删除主要服务于长期记忆的空间管理，日常淡忘不要求消除模型学习。压缩或清理记忆后，已经形成的性格、偏好、候选与在用训练产物可以保留，不自动回滚性格、停用模型或重新训练。

原始证据已清理时，成长记录与训练清单可以保留来源标识及“原文已清理”状态，不为维持追踪而重复保留完整正文。未使用的冗余样本可按空间策略清理；明确标记不再参与训练的内容不进入新批次。已有训练成果与今后是否继续使用原始样本分别控制。

已经进入模型权重的信息，不会因为删除数据库记录而可靠地消失。当前产品不以参数反学习为目标，也不把移除向量或删除 JSONL 描述为完成了权重遗忘。精确往事仍以可检索档案为依据，不能将模型残留的印象当作已核实的共同经历。

已导出副本和外部训练服务的留存需要按实际去向管理；应用只能如实说明其能清理和验证的范围。

## 九、验收方向

- 同一初始模板经过不同的有证据互动后，兴趣或表达倾向可以逐步分化；一次偶发对话不会剧烈改变长期性格。
- 成长更新来源可查、幅度受限，可暂停和回滚；模型自生成内容不产生无限自我强化。
- 更换聊天模型、迁移主机、恢复备份后仍有原始模板、当前档案与版本历史。
- 数据集能按来源追踪、脱敏、排除和删除；训练 / 测试近重复不穿越划分。
- 候选模型不通过评估时不替换当前模型；空间整理保留已有学习成果，来源原文被清理后状态可查，界面不伪称权重已被遗忘。
- 开启后无需手动选样或逐批确认即可完成样本处理、微调、评估与启用；条件不足会等待，不伪报成功。
- 关闭后排队任务不运行、在途任务无法部署；重新开启不自动补学排除范围，私密会话、明确排除内容与已清理且无法读取的来源不进入新批次。
- 训练忙时聊天优先，重启后任务状态可恢复；失败候选不启用，合格版本在请求边界切换，异常可回退。
