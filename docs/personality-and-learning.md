# 性格养成与训练设计

状态：用户希望有可选择的初始性格，性格在长期相处与探索中逐渐养成，并能在需要时将对话整理成数据集用于训练。下面是实现建议，尚未实现性格更新、数据导出或模型训练。

## 一、把成长分成三个层面

| 层面 | 保存什么 | 如何改变 | 是否需要训练模型 |
| --- | --- | --- | --- |
| 记忆 | 经历、约定、事实与来源 | 交流后增量提取、检索、纠错与归档 | 不需要 |
| 性格与行为 | 表达习惯、兴趣、交流节奏、对特定场景的应对方式 | 根据多次互动与反馈形成有来源、可回滚的版本 | 不需要 |
| 模型能力与风格 | 模型参数或独立适配器 | 使用经过整理的数据离线训练、评估后切换 | 需要，且取决于模型与供应商支持 |

前两层即可实现持续的适应与成长，并保持日常聊天响应速度。模型训练可以在积累足够合适的样本后进行，不必每次聊天都更新权重。换模型时，记忆与性格档案仍可继续使用；实际表现需要重新验证。

## 二、初始性格是起点

可提供温和、活泼、沉静、好奇等初始模板，也可以自定义。不把一个类型标签当成永远固定的全部性格。

建议保存：初始模板与版本、表达倾向、兴趣主题、好奇程度、幽默程度、交流节奏，以及当前使用的简短行为描述。具体维度与界面在产品迭代中确定，不把这些维度宣称为真实的人类心理测量。

初始档案、后续性格版本和当下对话状态分开。一次用户生气、一段角色扮演或助手的一句偶然表达，不应立即重写长期性格。诚实陈述来源、保护凭据和设备操作权限等基础规则独立维护，不随性格养成改变。

## 三、渐渐养成的流程

1. 从尚未处理的互动、用户纠正、明确反馈与实际任务回执中收集候选观察，记录来源与时间。
2. 区分用户喜好、yf 已表现出的表达习惯、暂时情境和模型推断；助手自生成的总结不作为独立证据反复强化。
3. 后台按阈值或空闲时段分析相关样本，生成幅度有限的成长提案，而非每轮重新总结全部历史。
4. 对照多次互动检查一致性和反例，先评估候选变化；少量证据保留为观察，不直接当作稳定特征。
5. 更新当前性格版本并记录变更原因、来源与父版本；只把当前短档案和少量相关兴趣放入聊天上下文。

一般的渐变可以按用户选定的规则自动进行，不必每次弹窗。涉及初始身份或明显交流方式变化时，提供可见说明与调整入口。支持查看成长记录、暂停养成、撤回某次变化与回到旧版本。

成长不只等于迎合每一句话。目标是积累稳定而有变化的表达方式、兴趣和思考习惯，遇到不确定的事实能保留疑问，用户纠正后可以修正认识。稳定程度和变化速度应可调整，实际参数通过长期对话样例评估。

## 四、探索与学习

第一步的探索来自对话：发现感兴趣但不了解的主题，保存尚未解决的问题，在合适时机追问，比较旧认识与新证据。兴趣与学习笔记记录形成原因、资料来源和不确定性，避免生成一次就被当作已验证知识。

外部检索、阅读资料、主动发起话题可逐步加入。后台学习设置计算 / API 用量、任务次数和执行时段；外部内容按不可信数据处理。自生成的问答与反思笔记可以作为候选材料，不能不经核验就不断回灌为真实经历或高质量训练样本。

探索不扩张设备操作权限。闹钟与电话仍走设备能力的校验和回执流程；读取新资料不等于可以自行联系别人或执行生成的命令。

## 五、从对话到训练数据集

用户在需要时发起数据准备，选择会话、时间范围或收藏样本。保存了聊天记录不等于已经上传给训练服务，也不等于所有记录都会成为训练样本。

建议流程：选定来源 → 脱敏与排除 → 整理上下文 → 审阅 / 修正回复 → 去重与分组切分 → 冻结版本 → 导出 → 训练与评估。

- 支持排除私密会话、凭据、联系人细节，以及用户标记不参与训练的内容；样本允许预览和修改。
- 助手原回答不自动代表好答案。错误、编造、失败的任务确认和用户否定过的回复应剔除或修正；系统回执不能由整理模型补造。
- 数据集记录预期目标，例如保持交流风格、减少某类答复错误；旧人格或角色扮演样本不一定适合当前目标。
- 以完整的局部对话构造样本，保存角色与必要上下文。常规监督训练以筛选后的助手回复为目标，不把用户输入、工具返回和系统规则一概作为助手输出训练。
- 使用按会话 / 事件分组、结合时间的训练 / 验证 / 测试划分，执行近重复检查；同一事件的改写不能同时泄漏到训练与测试中。
- 通用导出可用 `messages` 形式的 JSONL，并用清单记录样本来源、人格版本、清理规则、划分与校验和。训练框架 / 服务商的具体格式通过单独导出适配器生成。
- 导出文件、清单与训练产物都属于用户私有数据，存放于独立数据目录，不提交源码仓库。

需要保存样本与来源消息的映射，才能在用户删除记录时找到受影响的数据集、候选模型与适配器。训练能力从建立数据来源与导出格式开始预留，不要求用户现在就选训练硬件。

## 六、训练与部署边界

可微调的本地开放权重模型可以评估 LoRA / QLoRA 等方式，先以独立适配器进行小规模实验，保留原始模型。其可用性取决于模型架构、许可证、训练工具与内存 / 显存；API 模型则仅在供应商明确支持微调时提供入口，不保证所有聊天 API 都能训练。

Mac mini 可以作为后续常开服务或某些本地模型的推理设备；是否适合目标训练任务需单独测算。训练也可在另一台设备完成，再将兼容的产物部署回服务主机。

训练任务有独立资源与费用预算，不阻塞前台聊天。记录基础模型精确版本、tokenizer、数据集版本、训练配置与产物校验和。适配器通常依赖特定基础模型，不能承诺更换任意模型后直接复用。

新产物先作为候选，验证交流风格、通用能力、事实准确性、记忆使用、隐私泄漏和设备任务的正确性后，再由用户选择启用。保留可用旧版本，支持切回；首阶段不自动用在线聊天滚动训练并替换在用模型。

个人往事仍以可检索档案作为事实来源。训练更适合改善表达与反应模式，不能保证精确保存每件往事，且可能增加个人内容被模型直接输出的风险。可以使用替换标识或脱敏版本训练表达，把实际姓名、号码等事实留给按需检索。

## 七、遗忘如何影响成长和训练

删除来源消息后，需要重新评估依赖它的性格变化、学习笔记和数据集；受影响的候选或在用训练产物应标记，并提供停用与替换路径。

已经进入模型权重的信息，不会因为删除数据库记录而可靠地消失。若要求该信息不再存在于在用模型中，需停用受影响产物，切回未使用该数据的干净版本，必要时用清理后的数据重新训练；这也适用于已经合并进权重的适配器。不能把移除向量或删除 JSONL 说成完成了模型遗忘。

已导出副本和外部训练服务的留存需要按实际去向管理；应用只能如实说明其能清理和验证的范围。

## 八、验收方向

- 同一初始模板经过不同的有证据互动后，兴趣或表达倾向可以逐步分化；一次偶发对话不会剧烈改变长期性格。
- 成长更新来源可查、幅度受限，可暂停和回滚；模型自生成内容不产生无限自我强化。
- 更换聊天模型、迁移主机、恢复备份后仍有原始模板、当前档案与版本历史。
- 数据集能按来源追踪、脱敏、排除和删除；训练 / 测试近重复不穿越划分。
- 候选模型不通过评估时不替换当前模型；删除训练来源时能识别受影响产物，界面不伪称权重已被遗忘。
