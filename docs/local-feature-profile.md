# 可迁移的本地特征档案

目标：将表达倾向、重要性判断侧重和行为样例保存在 yf 本地，构建请求时传给所选模型，减少切换 API 后的风格变化。应用特征值不是神经网络权重，不能保证不同模型产生相同回答。

## 一、各类数据怎样保存和使用

| 内容 | 本地表示 | 什么时候发送 |
| --- | --- | --- |
| 单条记忆的重要性 | 每条事件的独立分值、理由与来源 | 该记忆被召回时随片段发送 |
| 记忆偏好 | 多个事件反馈形成的主题偏置与证据数 | 记忆整理时发送有上限的偏好摘要 |
| 初评侧重 | 明确重视、个人意义、长期相关性的相对权重 | 记忆整理时归一化后发送，作为模型判断的辅助依据 |
| 表达倾向 | 温暖、幽默、好奇、直接、展开、话题主动六个数值 | 每次聊天编译为带数值的简短文字说明 |
| 行为细节 | 最多 500 字的补充描述 | 随当前表达档案发送；转义后超出预算时缩短本次发送内容，本地原文保留 |
| 风格样例 | 最多三组用户话语和理想回应 | 按约 2,000 字符的档案预算整组加入；放不下的样例省略 |
| 未来微调特点 | 经过对比验证的行为描述与代表样例 | 可写入上述行为档案；自动总结尚未实现 |

具体往事不能全被几个数字代替，仍使用原始档案和按需记忆检索。不需要每次读取完整聊天，也不需要把整个档案库发给 API。

## 二、数值需要语义解释

例如 `humor=0.35` 本身没有跨供应商通用的含义。yf 会一起发送“幽默倾向 0.35：适量轻松幽默”，并说明应按当前场景调整。主动程度只控制对话中的话题提议，不授予主动通知、拨号等设备权限。

初始数值是可调整的工程起点，不是心理测量结果。当前版本由用户在“偏好与连接 → 本地特征档案”手动调整；对话驱动的自动性格演化仍待实现。既有的记忆反馈适应继续独立运行，不需要开启微调。

## 三、微调特点怎样迁移

未来可以让基础模型和微调模型回答同一组固定问题，对比稳定出现的表达方式、解释习惯与场景行为，将有证据的差异提炼成描述与样例，再用新 API 验证效果。

这是一种行为层面的提炼，不能导出闭源 API 的内部参数，也不能保证复制微调获得的知识、推理能力或所有场景反应。LoRA / 模型权重仍单独保存并绑定基础模型，不能作为几个标量直接交给任意聊天 API。

## 四、当前实现

- `feature_profiles` 保存完整的版本快照、时间和更新方式，独立于 API 配置。
- 保存时检查预期版本，阻止两个页面互相覆盖；回退会建立新版本，保留历史。
- 聊天使用表达档案与预算内样例；整理器只读取重要性判断侧重，不从风格样例提取个人事实。
- JSON 导出和 SQLite 备份包含特征历史；换模型时继续从同一数据库加载。
- 数据库从 schema 1 升至 2 前自动建立一致性备份，保留旧人格文字和记忆。schema 1 / 2 备份均可恢复到新目录，再由当前版本升级。
- 手动写入的描述和样例与聊天原文是独立记录，历史版本也会保留；目前不会自动关联它们与被删除聊天之间的来源关系，因此不要把这里当作事实档案自动复制个人经历。

## 五、接口

```text
GET  /api/profile          当前版本及完整档案
PUT  /api/profile          expected_version + document，保存为新版本
POST /api/profile/restore version + expected_version，回到指定内容并新建版本
GET  /api/status           包含当前档案、最近 30 个版本和记忆偏好
```

完整字段定义以自动生成的 `/docs` 接口文档为准。尚未接入真实模型时，可以验证数据保存和请求内容，但不能据此承诺某个供应商的实际风格还原效果。
