## 技术建议，尚待讨论

| 编号 | 建议 | 说明 |
| --- | --- | --- |
| P001 | Flutter 共用 Windows / Android 客户端 | 如果桌面原生能力或团队技术偏好更重要，可再比较其他方案 |
| P002 | Python + FastAPI 提供模型与记忆服务 | 适合当前记忆处理目标；需解决桌面分发与后台任务生命周期 |
| P003 | SQLite + sqlite-vec 起步，检索接口可替换 | 先验证个人数据规模，达到性能瓶颈后迁移索引 |
| P004 | 同一服务拥有一份主记忆库 | 首阶段多端通过服务共享数据；离线多主同步另行设计 |
| P005 | 先做服务与记忆闭环，再完善 Windows，随后交付 APK | 保留完整跨平台目标，以可验证的小版本推进 |
| P006 | 将重要档案长期保存与日常检索权重分开 | 降低召回频率不等于删除，珍藏原文不被摘要替代 |
| P007 | 日常任务通过设备系统接口执行并返回回执 | 已设置的手机闹钟独立于模型服务；电话先从系统拨号入口做起 |
| P008 | 备份、迁移、导出与来源关系从数据层初期实现 | 支持未来迁至 Mac mini 等主机，更换模型后保留记忆 |
| P009 | 将记忆、性格渐变和参数训练分层实现 | 日常养成通过可版本化的短档案完成，训练独立评估与切换 |
| P010 | 数据集可筛选、脱敏、追溯与导出，模型产物有数据血缘 | 支持按需训练，明确数据库遗忘与权重遗忘的差别 |
| P011 | 学习开关覆盖性格更新与微调，记忆保存独立控制 | 关闭暂停新增学习，保留已有成果；历史补学与重置另行选择，具体默认值为建议 |
| P012 | 记忆偏好调整属于记忆功能，独立于性格养成和模型微调 | 先响应具体事件反馈，再根据多条独立证据适应主题偏好；不按助手召回次数自我强化 |

## 下一轮重点

1. 陪伴体验：初始性格类型、成长速度、探索范围，以及主动问候 / 回忆提醒是否需要、如何控制频率。
2. 首先使用哪个模型来源：本地还是 API？若本地，需了解显卡 / 显存与内存；若 API，只需先确定服务商，密钥不写入讨论文档。
3. 是否接受 Flutter + Python 的组合，以及 Windows 首发优先级。
4. 实际使用后的记忆提取质量、淡忘速度、追问频率与细节层级；不需要用户逐条手动判分。
5. 开源许可证、Windows 安装形式、Android 最低版本与后续发布渠道。
6. 静默学习的训练位置、资源 / 费用预算与初始默认值；训练目标需要模型或供应商支持微调。

这些待定项不影响本次建立仓库，但会影响下一步代码骨架和具体交付范围。每次决定后更新本文件，避免把草案误当作已经确认的需求。
