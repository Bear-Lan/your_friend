# 陪伴界面与角色

## 原生客户端

Windows / Android 使用 Flutter 原生渲染，不使用 WebView。两个平台连接同一个 yf 记忆服务、同一条持续聊天 `yf-companion`。更换角色或模型服务不会删除记忆和本地特征档案。

Windows 默认以约 220 × 320 逻辑像素的透明无边框桌宠显示在屏幕右下角，点击展开约 420 × 640 的聊天面板，关闭按钮收回桌宠。拖动角色或聊天顶部移动窗口；右键角色或系统托盘图标可访问聊天、衣橱、设置、置顶开关和退出。窗口会限制在显示器工作区内，随 DPI 变化调整。关闭聊天面板保留草稿、聊天状态和正在接收的回答。

Android 使用正常的手机聊天页面，角色在上方，衣橱 / 回忆 / 设置位于可关闭面板中。客户端没有创建或切换对话的入口。历史分页读取，模型输入仍受上下文预算控制。

## 当前美术资源

按用户选择，先采用项目本地、可替换的二次元 2D 立绘。资源位于 `apps/client/assets/characters/`，SVG 源码和 PNG 随项目保存，生成脚本为 `tools/make-character-assets.py`，没有调用图片 API。三套配色共用角色轮廓，并不是独立的服装模型。

待机动作是轻微上下浮动，支持暂停和系统减少动态效果选项；它不是 Live2D、3D 骨骼或口型同步。后续可接入精细立绘、Live2D 或 VRM，角色资源与记忆层独立。外部资产导入 UI 尚未实现，目前替换素材后需重新构建。

## 开发用网页

服务在 `127.0.0.1:8765` 保留早期网页，便于检查记忆、反馈、导出和备份。网页原型使用 Three.js 0.180.0 和程序化几何角色；其外观不是当前桌宠设计。Three.js 资源保存在 `services/memory_api/yf/web/vendor/`，保留 MIT 许可证，不依赖运行时 CDN。

## 验证与边界

客户端测试覆盖窄屏 / 宽屏、衣橱持久化、桌宠收起展开后草稿和聊天保留、SSE 中文分块与断流错误。Windows runner 单独编译验证；透明效果、多显示器和托盘行为仍需要真实桌面持续验收。

实际 API 可用性独立于客户端：模型已配置不代表供应商有可用通道。失败显示真实错误。自动性格养成、训练、语音、系统闹钟、拨号、手机离线推理仍待实现。
