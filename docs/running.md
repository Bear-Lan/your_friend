# 运行本机验证版

本版是模型与记忆链路的首个可运行原型，使用 FastAPI 和简单网页。它不是 Windows 安装包，也不是 Android APK。Flutter 客户端、手机配对与后台微调还没有实现。

## 启动

需要 Python 3.12 或以上，以及首次安装依赖时的网络连接。当前开发机已在仓库内建立独立的 `.venv`，没有向全局 Python 安装项目依赖。

Windows 可以双击根目录的 `start-yf.cmd`，保留运行窗口；关闭窗口将结束服务。已有服务时直接打开 [本机页面](http://127.0.0.1:8765)。当前启动器是开发辅助脚本，不是独立安装包。

推荐开发命令（在仓库根目录执行）：

```powershell
uv sync --frozen --extra dev
.venv\Scripts\python.exe -m yf
```

不使用 uv 时：

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -e ".[dev]"
.venv\Scripts\python.exe -m yf
```

随后打开 `http://127.0.0.1:8765`。命令行可加 `--open` 自动打开浏览器，或用 `--port 8766` 指定其他端口。数据目录有单实例锁，不能同时打开两个服务操作同一主库。

## 连接模型

复制根目录的 `.env.example` 为 `.env`，只在本机填写：

```dotenv
YF_MODEL_BASE_URL=http://127.0.0.1:11434/v1
YF_MODEL_NAME=你已经安装或开通的模型名称
YF_MODEL_API_KEY=
```

本地推理服务需要自己先安装、启动并下载对应模型。云端 API 使用供应商提供的兼容接口地址、模型名和密钥。地址填写接口前缀，例如带 `/v1` 的地址，程序会追加 `/chat/completions`。

配置变更后重启 yf。页面“已配置”表示配置存在，实际连通性以发送消息的结果为准；没有模型时，聊天会明确提示不可用，手动记忆、反馈、检索、导出与备份仍可使用。

`YF_MEMORY_MODEL` 可以指定同一接口下用于整理记忆的另一模型，留空则使用聊天模型。模型需支持文本流式回答和按指令输出 JSON；不支持时会显示错误，后台最多有限重试，不伪报整理成功。

普通聊天与记忆整理都会使用这个接口。云端模式会发送本轮消息、受限的近期上下文和相关记忆；后台整理也会发送相关片段并可能产生费用。可在“偏好与连接”关闭后台自动整理。

## 当前可以体验的内容

- 流式聊天、新建会话、历史分页、请求去重、停止后保留已收到的部分回答；中断或失败有明确状态。
- 原始聊天默认长期保存；前台只加载受预算约束的近期消息和相关记忆。
- 成功对话进入持久化后台任务。模型从用户消息提取少量事实 / 事件，保存判断理由、来源、重要度、置信度与已知缺口。
- 手动新增记忆，调整重要性、珍藏，查看原文及已淡去的归档细节。
- 本地特征档案：六项表达倾向、重要性判断侧重、补充行为描述与最多三组风格样例，支持版本保存与回退；聊天请求携带精简档案，记忆整理读取判断侧重。换 API 仍使用同一份档案，但实际表现由所选模型决定，详见 [本地特征档案](local-feature-profile.md)。
- 低重要度先淡去细节，再淡出日常召回；珍藏不自动淡去。日期推进用测试验证，不改电脑时间模拟。
- 通过页面反馈或当前对话中的明确反馈调整事件重要性；模型只能反馈已提供的相关记忆。至少三个不同事件的同主题反馈后，产生有上限的主题偏好，用于后续新记忆评分。这不是权重微调，也不是已经实现完整的偏好推断。
- 查询旧聊天、JSON 导出、SQLite 一致性备份，以及恢复到新目录的命令。

“记忆保存”和“后台自动整理”分别控制。暂停记忆保存会暂停新增记忆和召回，但不删除原文与既有记忆；暂停自动整理后仍可手动记录。高级性格养成和微调开关尚未实现，界面明确显示能力状态。

## 预算与尚未实现的部分

本版前台使用字符预算：输入正文总计约 14,000 字符、近期消息最多约 8,000 字符、召回记忆约 2,500 字符，当前用户输入最多 5,000 字符。最近完整对话轮次在预算内加入，不完整截断当前用户消息。字符预算不等于实际模型 token 数；模型窗口仍需自行匹配，后续接入精确 tokenizer。

表达档案约束在 2,000 字符内，并计入上述总预算；样例以整组为单位加入。当前特征由用户手动调整，不表示已完成自动性格学习或从微调权重提炼特点。手动档案及历史样例属于独立记录，删除聊天不会自动删除手动复制到这里的内容。

检索采用 SQLite FTS5 和中文字符组合 / 英文关键词，不具备真正的语义向量召回，改写表达可能漏检。日常检索与归档查询分开；索引只查有限候选，前台不读取全部历史。滚动会话摘要、复杂事件合并、自动性格演化、完整偏好学习、向量检索和多年规模的性能评估都还没有完成。

淡忘参数是初始实验值：重要性低于 0.3 的半衰期为 3 天，普通为 30 天，高重要性为 365 天；这控制可用细节层级，不清理原始档案。阈值需根据真实体验调整，没有声称模拟出了真实的人类记忆。

服务仅监听本机，检查 Host、Origin 与请求来源，不提供手机配对或多用户隔离；不要通过代理把这一验证版暴露到公网或局域网。后续实现设备令牌与受保护连接后再开放手机连接。

## 数据、删除与恢复

默认数据位于仓库 `.local/yf.sqlite3`，SQLite 的 WAL / SHM 文件由数据库管理；备份位于 `.local/backups/`。这些内容均被 Git 忽略。`YF_DATA_DIR` 可设置独立目录，仓库内的相对路径始终按仓库根目录解析。

本地特征功能将数据库 schema 升至 2。升级前自动在 `backups/` 创建 `before-schema-2-*.sqlite3` 一致性快照，既有聊天、记忆与人格文字保留；旧程序不能直接打开升级后的数据库，需使用当前程序或旧版快照。

记忆“删除”先展示关联范围，再在一个事务内清理相关记忆、来源消息和使用过该记忆的回答，同时阻止相关整理任务再次写入。当前以整个关联对话轮次为保守清理单位，可能连带其他事实，必须看清预览；精细到文本片段的删除尚未实现。它是在线数据的逻辑清理，不承诺擦除磁盘空闲页、旧备份、已导出副本或模型服务商留存。

JSON 导出用于查看与后续迁移，尚无 JSON 导入器。完整恢复使用页面下载的一致性 SQLite 备份：

```powershell
.venv\Scripts\python.exe -m yf --restore-backup E:\your-backups\snapshot.sqlite3 --restore-to E:\your-backups\yf-recovered
```

恢复命令验证数据库完整性与版本，只写入新数据库，拒绝覆盖已有主库，不自动切换在用服务。旧快照可能包含后来已删除的信息；本版还不会自动重放新主库的删除记录，需要在切换前自行检查和清理。验证恢复副本后，停止服务，将 `.env` 的 `YF_DATA_DIR` 指向新目录再启动；原目录保留供回退。

## 验证

```powershell
uv run --frozen pytest -q
uv run --frozen ruff check .
uv run --frozen ruff format --check .
node --check services/memory_api/yf/web/app.js
```

自动化测试使用专用测试模型和临时数据，不调用真实供应商，也不代表已经验证某个真实模型的召回质量。CI 配置覆盖 Windows / Linux 与 Python 3.12 / 3.14，远端执行结果需另外查看。
