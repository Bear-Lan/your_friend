# 单一陪伴页面与立体形象

已确认：yf 只有一个持续聊天的主页面，不以创建和切换多段会话组织陪伴，希望以立体虚拟人为交流中心。

## 当前实现

- 主页面：立体伙伴、连续聊天与输入区；轻紫色场景，桌面左右布局，小屏上下布局。
- 回忆 / 设置：可关闭的侧面模态抽屉，保留珍藏、反馈、原文检索、特征档案、导出与备份。打开抽屉时暂停 3D 渲染，聊天流不被中断。
- 连续聊天：幂等的 `POST /api/companion` 使用数据库中的固定会话 `yf-companion`，各浏览器和服务重启后返回同一标识；历史分页读取，每次模型输入仍受预算限制。
- 旧版会话保留原始数据，通过回忆中的原文检索查看当时片段；不会静默合并或删除旧记录，也不把当前聊天切换成旧会话。兼容会话 API 仍保留，但不作为新界面入口。
- 角色：由几何体构建的风格化人形，包含头发、五官、衣服、手脚、光照、阴影与底座。呼吸、眨眼、轻微视线跟随、点击挥手均在本地运行；实际请求状态驱动思考 / 回应动作，API 失败有明确提示，不生成假的模型回应。
- 动态控制：限制约 30 帧与像素比例；隐藏标签页 / 打开抽屉时不渲染；暂停动作后只在需要时绘制。默认遵循系统减少动态效果设置，可用按钮覆盖当前页面行为。
- 降级：WebGL 初始化失败或上下文丢失时显示静态提示，文字聊天、回忆与设置仍可用。

## 资源与可替换范围

渲染使用 Three.js 0.180.0，来自官方 npm 包。本地文件位于 `services/memory_api/yf/web/vendor/`，保留其 MIT 许可证 `three.LICENSE`。构建包包含这些文件，不在用户打开页面时向公共 CDN 请求脚本。项目整体许可证仍待确定。

当前角色是可直接运行的程序化形象原型，没有加载 VRM / glTF 真人资产；不包含语音、口型同步、摄像头识别或模型自主情绪推断。动作由本地交互和生成状态驱动，不宣称代表模型真实情绪。

角色外观与记忆、性格档案相互独立。后续可以替换为经过许可的 VRM / glTF 角色，并增加骨骼动画、表情与语音口型，原有聊天和记忆继续沿用。当前具体美术方向属于可修改的工程起点。

## 验证

后端测试覆盖多次连接获取同一聊天、发送消息后服务重启仍保留历史、旧记录可按来源定位且不切换固定聊天。浏览器检查主页面 WebGL 显示、抽屉开闭、暂停与挥手入口。真实 API 可用性与 UI / 本地动作分开验证；配置成功不代表供应商当前可以生成回答。
